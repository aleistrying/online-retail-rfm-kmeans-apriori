# Online Retail — RFM Clustering & Market Basket Mining

I mined a real UK online retailer's transaction log to segment customers by purchase behaviour
(K-Means on RFM features) and to find products that get bought together (Apriori association
rules).

**Course** — Coursework, Lambton College, CBD-3333 Data Mining (Summer 2026).
**Team** — Solo project.

## The problem

Given 541,909 raw retail transactions, three tasks: (1) clean the data and engineer features,
(2) segment customers with K-Means so a business could target them differently, (3) find
co-purchase patterns with Apriori that a store could use for bundling/placement.

## The data

UCI **Online Retail Data Set** — 541,909 transactions, Dec 2010–Dec 2011, one UK-based online
gift retailer. Columns: InvoiceNo, StockCode, Description, Quantity, InvoiceDate, UnitPrice,
CustomerID, Country.

- Dataset page: https://archive.ics.uci.edu/dataset/352/online+retail
- Not committed here — see `data/README.md` for the download link and where to place it.

## Approach

1. **Preprocessing** — dropped rows missing `CustomerID` or `Description`, removed cancelled/
   non-positive-quantity rows and duplicates, engineered `TotalPrice = Quantity × UnitPrice`,
   one-hot encoded `StockCode`/`Country` to demonstrate the technique (not fed into the models —
   3,700+ product columns would swamp the clustering distance metric), and standardized the
   numeric features.
2. **Customer clustering** — built RFM (Recency, Frequency, Monetary) features per customer,
   log-transformed and standardized (RFM is heavily skewed), then used the Elbow Method and
   silhouette score to choose *k* for K-Means.
3. **Association rules** — converted transactions to a sparse basket matrix (one row per
   invoice) and ran Apriori at the assignment's required thresholds, then again at a lower
   support on the top-80 products to get interpretable rules, ranked by lift.

## Results

From the full-dataset run (`report/report.md`, `report/outputs/task2_rfm_clusters.csv`,
`report/outputs/task3_rules.csv` — all regenerated by `notebook/online-retail-mining-script.py`,
a plain-Python version of the notebook logic written to avoid an out-of-memory crash from
densifying the one-hot matrix):

- **Clustering**: 4,338 customers, silhouette score peaked at **k = 2** (score 0.433).
  - Cluster 0 (2,672 customers): avg recency 134 days, avg frequency 1.7, avg spend £496 —
    lapsed/low-value.
  - Cluster 1 (1,666 customers): avg recency 26 days, avg frequency 8.4, avg spend £4,540 —
    loyal/high-value.
- **Association rules**: at the required thresholds (min_support=0.15, min_confidence=0.5),
  Apriori found **0 frequent itemsets** — no single product appears in 15% of all baskets, so
  the threshold is simply too strict for this dataset. Re-run on the top 80 products at
  min_support=0.02 produced 142 itemsets and 37 rules; top rule by lift: "Green Regency Teacup +
  Cakestand 3 Tier → Roses Regency Teacup" (support 0.021, confidence 0.83, **lift 15.5**).

**Caveat on the notebook's own saved output:** `notebook/online-retail-mining.ipynb` has a
`SAMPLE_SIZE` testing toggle, and its last saved run (`SAMPLE_SIZE = 20000`) shows different,
smaller numbers in its own output cells (527 customers, a much larger raw rule count before
filtering) than the full-dataset numbers above. The full-dataset numbers in this README come
from the companion script (`online-retail-mining-script.py`) and are backed by the CSVs in
`report/outputs/`. Re-running the notebook with `SAMPLE_SIZE = None` reproduces the same
full-dataset numbers.

## How to run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# get the data first — see data/README.md
jupyter notebook notebook/online-retail-mining.ipynb
# or, for the full dataset without notebook memory overhead:
python notebook/online-retail-mining-script.py
```

## What I'd do next

- Re-run the notebook itself end-to-end with `SAMPLE_SIZE = None` so its saved outputs match
  the full-dataset numbers, instead of relying on the separate script.
- Try a segmentation beyond 2 clusters (e.g. inspecting k=3/4 despite the lower silhouette) to
  see if a business would find a finer split more actionable.
- Look at rules per country instead of globally — the UK dominates the data and may be masking
  different co-purchase patterns elsewhere.
